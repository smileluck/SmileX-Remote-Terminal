## 一、产品概述

### 1.1 产品定位

SmileX-Remote-Terminal 是一款 **跨平台综合运维工具**，融合三大核心能力：

1. **SSH 终端**（类似 Xshell/MobaXterm）—— 命令行运维
2. **远程桌面**（类似 Windows mstsc）—— 图形化运维
3. **AI 运维助手** —— Chat 智能问答 + Work 自主执行（预留）

三大能力以独立标签平级管理，覆盖命令行与图形化两种运维场景，并内置 AI 辅助。

### 1.2 产品目标

| 目标 | 衡量指标 |
|------|---------|
| 提供流畅的多标签 SSH 终端体验 | 大输出（GB 级）不卡顿、不 OOM |
| 提供全平台流畅的远程桌面 | Windows/Linux 用 RDP、macOS 用自研被控服务，延迟 < 200ms |
| 提供 AI 智能运维助手 | 结合当前会话上下文回答运维问题 |
| 隐私优先 | 凭据纯本地存储，无云端中转，无后台数据外传 |
| 跨平台一致体验 | Windows / macOS / Linux 三端功能一致 |

### 1.3 产品背景与痛点

| 现有方案 | 痛点 | 本产品对策 |
|---------|------|-----------|
| Xshell | 仅 Windows、收费 | 跨平台、免费开源 |
| VNC 连 macOS | Retina 屏卡顿严重（单帧 24MB） | 自研被控服务（ScreenCaptureKit + VP9 硬编）根治 |
| TeamViewer/ToDesk | 商业限制、数据过云 | 纯本地、凭据不出本机 |
| 传统运维无 AI 辅助 | 报错需手动查 | AI Chat 结合终端上下文作答 |

### 1.4 名词术语

| 术语 | 含义 |
|------|------|
| 控制端 | 本应用（Tauri 桌面程序），发起连接 |
| 被控端 | 被远程操作的目标设备 |
| 被控服务 (Host Service) | 部署在被控 macOS 上的轻量程序，负责屏幕捕获+编码+传输。**不叫 Agent**（避免与 AI Agent 混淆） |
| AI Agent | 本应用内置的智能运维助手模块（Chat/Work 两种模式） |
| RDP | Remote Desktop Protocol，Windows/Linux 远程桌面协议 |
| SessionKind | 会话类型枚举：`ssh` / `rdp` / `host` / `chat` |

## 二、用户角色与使用场景

### 2.1 用户角色

| 角色 | 描述 | 核心诉求 |
|------|------|---------|
| 运维工程师 | 管理大量服务器 | 批量 SSH 管理、快速远程桌面、命令记忆 |
| 后端开发 | 连测试/生产服务器 | SSH 调试、文件上传下载、端口转发 |
| DBA | 维护数据库服务器 | SSH + 远程桌面混合使用、安全合规 |
| 个人开发者 | 管理个人 VPS/家用机 | 免费跨平台、隐私安全、AI 辅助 |

### 2.2 典型使用场景

**场景 1：SSH 批量运维**
> 运维工程师管理 50+ 台 Linux 服务器，需同时打开多个终端执行命令、对比输出。本工具提供多标签 + 会话管理 + 大输出不卡顿。

**场景 2：Windows 服务器图形化操作**
> DBA 需登录 Windows SQL Server 进行图形化管理。本工具用 RDP 直连（系统自带服务，零部署），体验接近本地。

**场景 3：macOS 远程开发**
> 开发者在外出差需远程操作办公室 Mac。部署被控服务后，通过 VP9 硬编流畅操作，对比 VNC 体验显著提升。

**场景 4：AI 辅助排障**
> 后端开发遇到终端报错，勾选"附带当前会话上下文"向 AI 提问，AI 结合实际报错输出给出解决方案。

**场景 5：文件同步**
> 开发者需将本地代码包上传到测试服务器。通过 SFTP 双面板拖拽传输，支持断点续传。

## 三、功能需求

> 优先级定义：P0 必须（MVP）、P1 重要、P2 可选/未来

### 3.1 会话与标签管理（P0）

| 编号 | 需求 | 优先级 | 验收标准 |
|------|------|--------|---------|
| F-SESSION-01 | 多标签管理，支持新增/关闭/切换/重命名 | P0 | 标签按 SessionKind 渲染对应视图 |
| F-SESSION-02 | 会话配置管理（增删改查） | P0 | 持久化到 SQLite，重启不丢失 |
| F-SESSION-03 | 会话分组与搜索 | P1 | 按分组/关键字过滤会话列表 |
| F-SESSION-04 | 统一 sessionId 空间，SSH/RDP/Host/Chat 共用 | P0 | 后端 SessionRegistry 统一索引 |
| F-SESSION-05 | 会话连接测试 | P1 | 配置时一键测试连通性 |

**SessionKind 枚举**：`'ssh' | 'rdp' | 'host' | 'chat'`

### 3.2 SSH 终端模块（P0）

| 编号 | 需求 | 优先级 | 验收标准 |
|------|------|--------|---------|
| F-SSH-01 | SSH 连接（密码/密钥认证） | P0 | 支持 Ed25519/RSA/ECDSA 密钥 |
| F-SSH-02 | PTY 终端交互（xterm.js 渲染） | P0 | 支持 ANSI 颜色、resize 同步 |
| F-SSH-03 | 大输出不卡顿/不 OOM | P0 | `cat` GB 级文件前端不崩溃（详见架构 §2.6） |
| F-SSH-04 | known_hosts 校验 | P0 | 首次弹窗确认指纹，不匹配告警 |
| F-SSH-05 | 终端主题/字体/配色设置 | P1 | 提供多套配色 |
| F-SSH-06 | 终端输出转存日志 | P1 | 超阈值输出转存本地文件，可查看 |

## 四、非功能需求

### 4.1 性能需求

| 编号 | 指标 | 目标值 |
|------|------|--------|
| NF-PERF-01 | 终端大输出 | GB 级输出前端不 OOM（scrollback 环形缓冲 + 转存） |
| NF-PERF-02 | 远程桌面延迟 | 端到端 < 200ms |
| NF-PERF-03 | 远程桌面帧率 | 30~60fps 自适应 |
| NF-PERF-04 | AI 流式响应首字 | < 1s（取决于 LLM） |
| NF-PERF-05 | SFTP 传输 | 充分利用带宽（并发分块） |
| NF-PERF-06 | 应用启动 | 冷启动 < 3s |

### 4.2 安全需求

| 编号 | 要求 | 实现方式 |
|------|------|---------|
| NF-SEC-01 | 凭据永不落盘明文 | OS Keyring（Win Credential Store / macOS Keychain / Linux libsecret） |
| NF-SEC-02 | 私钥/passphrase 不外传 | 纯本地，无网络上传 |
| NF-SEC-03 | SSH known_hosts 校验 | 首次确认 + 后续比对，防中间人 |
| NF-SEC-04 | SSH 算法白名单 | 禁用过时算法，优先 curve25519/chacha20-poly1305 |
| NF-SEC-05 | RDP NLA 认证 | CredSSP + NTLM/Kerberos |
| NF-SEC-06 | macOS 被控服务加密 | TLS 1.3 全链路 |
| NF-SEC-07 | LLM API Key 安全 | 存 Keyring，显式用户发起调用 |
| NF-SEC-08 | AI 隐私保护 | 上下文采集默认关闭需勾选；Ollama 模式数据不出本机 |
| NF-SEC-09 | 配置文件加密 | SQLite 可选 AES-256-GCM 加密 |

### 4.3 可用性需求

| 编号 | 要求 |
|------|------|
| NF-USA-01 | 跨平台 UI 一致（Tauri + Vue3） |
| NF-USA-02 | 多标签交互符合主流习惯（类浏览器/Xshell） |
| NF-USA-03 | 首次使用引导（权限授予、Provider 配置） |
| NF-USA-04 | 错误提示清晰可操作 |

### 4.4 兼容性需求

| 平台 | 控制端 | 被控端 |
|------|--------|--------|
| Windows | ✅ 10/11 | ✅ 自带 RDP |
| macOS | ✅ 12.3+ | ✅ 部署被控服务 |
| Linux | ✅ 主流发行版 | ✅ xrdp |

### 4.5 可扩展性需求

| 编号 | 要求 |
|------|------|
| NF-EXT-01 | 模块化架构，低耦合高内聚 |
| NF-EXT-02 | Provider trait 抽象，可扩展新协议/LLM |
| NF-EXT-03 | AI Work 模式 trait 预留，未来不改接口扩展 |
| NF-EXT-04 | 插件化命令分组，便于扩展 |

### 4.6 可靠性需求

| 编号 | 要求 |
|------|------|
| NF-REL-01 | 远程会话断线自动重连（可配次数/间隔） |
| NF-REL-02 | 端口转发连接无泄漏（超时+主动 cancel） |
| NF-REL-03 | Tauri 后端长任务不丢失（全局 AppState 持有） |

## 五、用户故事（User Stories）

### 5.1 SSH 运维

> **作为** 运维工程师，**我希望** 能在一个窗口里打开多个服务器终端并自由切换，**以便** 高效对比和执行命令。

> **作为** 后端开发，**我希望** 执行 `cat huge.log` 时前端不卡死，**以便** 快速查看大日志。

### 5.2 远程桌面

> **作为** DBA，**我希望** 用 RDP 直连 Windows SQL Server（无需装额外软件），**以便** 图形化管理。

> **作为** 开发者，**我希望** 远程操作 Mac 时画面流畅不卡顿，**以便** 像本地一样工作。

### 5.3 AI 助手

> **作为** 运维新人，**我希望** 遇到报错时 AI 能结合我终端的实际输出给建议，**以便** 快速排障。

> **作为** 注重隐私的用户，**我希望** 能用本地 Ollama 模型，数据不出本机。

### 5.4 文件与转发

> **作为** 开发者，**我希望** 拖拽上传代码包到服务器，**以便** 快速部署。

> **作为** 后端开发，**我希望** 通过端口转发访问内网数据库，**以便** 本地调试。

## 六、约束与假设

### 6.1 约束

- 纯桌面应用（基于 Tauri），不做 Web 端
- 凭据纯本地管理，不依赖云端服务
- 被控端：Win/Linux 用系统自带 RDP；macOS 需部署被控服务
- 控制端需用户自行配置 LLM Provider 与 API Key

### 6.2 假设

- 用户具备基础运维知识（懂 SSH/RDP）
- macOS 被控机为 12.3+（ScreenCaptureKit 要求）
- 网络可达被控端（直连或 VPN）

## 七、验收标准（MVP 范围）

MVP 完成后需满足以下全部验收项：

### 7.1 功能验收

- [ ] 多标签 SSH 终端：连接、交互、resize、大输出不卡顿
- [ ] RDP 远程桌面：连接 Win/Linux，画面+输入+剪贴板
- [ ] macOS 被控服务：部署后流畅连接（对比 VNC 提升）
- [ ] AI Chat：配置 Provider 后能流式问答 + 上下文作答
- [ ] SFTP：双面板拖拽传输 + 断点续传
- [ ] 端口转发：Local/Remote 启停
- [ ] 密钥管理：生成/导入/存储
- [ ] 会话配置：增删改查 + 持久化

### 7.2 非功能验收

- [ ] 三平台（Win/macOS/Linux）控制端可构建运行
- [ ] 凭据存 OS Keyring，配置存 SQLite
- [ ] 单元测试覆盖核心模块（ssh-core/remote-desktop-core/ai-core）
