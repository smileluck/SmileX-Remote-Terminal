# 服务器监控面板分类 Tab 改造

## 目标
将右栏监控看板(MonitorDashboard)拆分为 **通用 / CPU / 内存 / 磁盘 / GPU** 五个 Tab;GPU 需新增后端采集(SSH 执行 nvidia-smi),"通用"为精简概览。

## 一、后端改动(crates/desktop)

### 1. `src/monitor/metrics.rs`
- 新增 `GpuInfo` 结构(`index/name/util_percent/mem_used_mb/mem_total_mb/temp_c: Option<f64>`),`RawMetrics` 加 `gpus: Vec<GpuInfo>` 与 `load5/load15: f64`
- `COLLECT_SCRIPT` 末尾追加 `==GPU==` 分节:`command -v nvidia-smi` 存在才执行 `nvidia-smi --query-gpu=index,name,utilization.gpu,memory.used,memory.total,temperature.gpu --format=csv,noheader,nounits`(无 GPU 机器零开销)
- `parse_output` 加 `"GPU"` 分支:按逗号解析 CSV 行,`name` 取中间列再 join(防名称含逗号);`parse_load_line` 改为解析前 3 个浮点 token → load1/5/15(Linux loadavg 与 macOS uptime 格式均兼容)
- 更新/新增单元测试:GPU CSV 解析、load5/15、原 `parse_linux_output` 补 GPU 分节样例

### 2. `src/events.rs`
- 新增 `MonitorGpu` serde struct(snake_case,同 `MonitorDisk` 风格)
- `MonitorMetricsPayload` 加 `load5/load15/gpus` 字段,均加 `#[serde(default)]`(兼容旧 JSON 反序列化,遵循项目 IPC serde 约定)
- 同步更新锁定字段命名的 serde 测试

### 3. `src/monitor/sampler.rs`
- payload 构造处填充 `load5/load15` 与 `gpus`(GpuInfo → MonitorGpu 映射)

## 二、前端改动(app/src)

### 4. `types/monitor.ts`
- 新增 `MonitorGpu` 接口;`MonitorSample` 加 `load5/load15/gpus`(snake_case 与后端一致)

### 5. 监控组件拆分(components/monitor/)
- **`MonitorDashboard.vue`** 改为容器:监控目标下拉 + naive-ui `NTabs type="segment" size="small"`(5 个页签)+ 各页签组件;SessionHealthList 移入"通用"页签
- 新增子组件(均从 `useMonitorStore().activeSamples` 自派生曲线数据,复用 MetricCard/Sparkline):
  - `tabs/GeneralTab.vue`:概览行(延迟/负载/运行时长)+ CPU/内存/网络↓↑ 摘要卡 + 磁盘 Top3(/ 优先,按容量排序)
  - `tabs/CpuTab.vue`:CPU 使用率卡 + load1 曲线卡 + load1/5/15 数值展示
  - `tabs/MemoryTab.vue`:内存卡 + Swap 进度条与已用/总量(swap_total=0 显示"未启用 Swap";数据已有,零后端成本)
  - `tabs/DiskTab.vue`:完整挂载点列表(去掉现有 top6 限制,可滚动),每行含容量/已用明细,≥85% 红色
  - `tabs/GpuTab.vue`:每 GPU 一卡(名称/利用率曲线/显存进度条/温度),`gpus` 为空显示"未检测到 NVIDIA GPU"
- `fmtBytes/fmtBps/fmtUptime` 抽到 `utils/format.ts`(现 MonitorDashboard 与 SessionHealthList 重复实现,拆分后各 tab 都要用)

## 已知取舍
- GPU 机器上 nvidia-smi 约增加 100–300ms exec 往返,会略微抬高显示的 latency_ms(默认 3s 采样间隔下可接受)
- AI 上下文注入(last_metrics)暂不追加 GPU 字段,留作后续
