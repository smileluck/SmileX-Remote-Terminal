# 修复 SSH 无法访问(认证失败 + 连上后终端空白)

## 根因

1. **认证失败报错**(当前症状):请求方向 serde 已被今天重构修好,连接首次真正走到认证步骤。三个候选原因被混成同一个"认证被拒"报错:
   - Keyring 取不到密码时,`useSshConnect.ts:23` 的 `secret || ''` 静默发送空密码;且 ConnectForm 的 password 字段无必填校验
   - russh 0.45 `authenticate_password` 只发 SSH `password` 方法,服务器只允许 keyboard-interactive 时(NAS 常见)无兜底
   - 密码过期/错误
2. **连上后终端必空白**(下一个必踩的 bug):`crates/desktop/src/events.rs` 的 `TerminalOutputPayload`/`AiTokenPayload`/`AiDonePayload`/`DesktopFramePayload` 无 `rename_all="camelCase"`,前端读 `sessionId` 恒为 undefined,输出全部被丢弃

## 修改内容

### 1. 前端:空密码快速失败(`app/src/composables/useSshConnect.ts`)
- `buildConfig` 中 `auth_type === 'password'` 且 `secret` 为空时,直接 throw `Error('未设置密码：请编辑会话填写密码后重试')`,不再发送空串

### 2. 前端:密码必填校验(`app/src/components/common/ConnectForm.vue`)
- `rules` 中给 `password` 加条件 validator:新建模式(非 edit)且 authType=password 时必填;编辑模式保持"留空不更新"

### 3. 后端:认证错误信息增强(`crates/ssh-core/src/connection.rs`)
- 密码为空 → 立即返回明确错误("密码为空：Keyring 未取到该会话密码…"),不让服务器拒绝
- 认证失败信息带上认证方式和主机:`认证被拒（{user}@{addr}，密码认证）：密码错误，或服务器未开启密码登录`

### 4. 后端:keyboard-interactive 兜底(`crates/ssh-core/src/connection.rs`)
- 密码认证失败且密码非空时,自动用 `authenticate_keyboard_interactive_start` 发起 keyboard-interactive,对所有 prompt 用密码应答(循环应答,上限 3 轮),成功则视为认证通过(russh 0.45 API 已核实可用:`authenticate_keyboard_interactive_respond(Vec<String>)` → Success/Failure/InfoRequest)

### 5. 后端:响应 payload 加 camelCase(`crates/desktop/src/events.rs`)
- `TerminalOutputPayload`、`AiTokenPayload`、`AiDonePayload`、`DesktopFramePayload` 加 `#[serde(rename_all = "camelCase")]`(前端类型声明已是 camelCase,无需改前端)
- **不动** `MonitorMetricsPayload`/`AlertFiredPayload`(前端读 snake_case,两侧一致)
- 仿 `connection.rs:581-617` 加 serde 形状测试锁定 `sessionId`/`keyFrame` 字段名(desktop crate 如缺 `serde_json` dev-dependency 则补)

## 验证

1. `cargo test -p ssh-core -p desktop` 通过(含新增形状测试)
2. 根目录 `pnpm tauri dev`(注意端口已改 6173)
3. 编辑 "Nas"(root@192.168.112.200)会话重新输入密码,保存并连接 → 终端应出现提示符、有回显
4. 若仍认证失败:用 `ssh root@192.168.112.200` 以同密码对照排查服务器端配置(PasswordAuthentication/PermitRootLogin);增强后的报错会标明认证方式,便于区分
