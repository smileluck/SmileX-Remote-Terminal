# SmileX Remote Terminal 优化方案

## 一、布局重构：水平左中右三栏（带折叠）

改造 `app/src/App.vue` 与 layout 组件：

- **左栏（会话管理）**：保留 `ActivityRail`（56px 图标栏）+ `SideBar`，为 SideBar 增加折叠/展开（折叠后仅剩图标列），折叠状态持久化到 localStorage
- **中栏（主工作区）**：`TabBar` + `MainContent` 不变（终端 / 远程桌面 / AI / 设置）
- **右栏（监控看版，新增）**：新建 `components/layout/MonitorPanel.vue`，默认 320px、可折叠、可拖拽调宽；TopBar 增加监控面板开关按钮
- 布局状态放入新 store `stores/layout.ts`（左/右栏折叠、右栏宽度）

## 二、监控看版（核心新功能）

### 后端（Rust）
1. **ssh-core 新增 exec 能力**：`SshSession::exec(cmd) -> String`，走非 PTY channel 执行命令并收集输出（russh `channel.exec`）
2. **新增 `crates/desktop/src/monitor/` 模块**：
   - `metrics.rs`：一次性采集脚本（兼容 Linux/macOS）：读取 `/proc/stat`、`/proc/meminfo`、`df`、`/proc/net/dev` 解析出 CPU%、内存、磁盘、网络 IO、负载、运行时间
   - `sampler.rs`：按 sessionId 定时（默认 3s）采样 tokio task，round-trip 耗时作为延迟指标
   - Tauri 事件 `monitor_metrics`（payload 含 sessionId + 指标 + 时间戳），events.rs 新增 `MonitorMetricsPayload`
3. **新命令**（commands/monitor.rs，注册进 main.rs）：
   - `monitor_start(session_id, interval_ms)` / `monitor_stop(session_id)` / `monitor_list()`
   - 断开 SSH 会话时自动停止采样（session_disconnect 钩入）
4. **会话健康面板数据**：TerminalStream 处增加收发字节计数（AtomicU64），`monitor_metrics` 事件中附带 → 右栏顶部显示各活跃会话的：连接状态、运行时长、延迟、上/下行流量

### 前端（Vue）
1. `services/monitor.ts`：invoke 封装 + `monitor_metrics` 事件订阅（按 sessionId 分发）
2. `stores/monitor.ts`：每会话保留滚动窗口（如 60 个采样点）
3. `components/monitor/MonitorPanel.vue` 及子组件：
   - `MetricCard.vue` + `Sparkline.vue`（自绘 SVG 折线，**不引入图表库**，保持轻量）
   - CPU / 内存 / 网络 IO / 磁盘用量 实时曲线卡片
   - 底部「会话健康」列表：各 SSH 会话状态灯、时长、延迟、流量
4. 多会话时右栏顶部可切换监控目标（默认跟随当前激活的 SSH tab）

## 三、体验优化

1. **Host Key 确认弹窗**：AcceptNew 策略下首次遇到未知指纹时，后端 emit `hostkey_confirm` 事件 → 前端对话框展示指纹（SHA256），用户确认后才继续（替代当前静默记录）
2. **连接失败/断开通知**：SSH 连接失败用 useNotification 展示原因；会话意外断开时 tab 标记为断开态并提供「重新连接」按钮
3. **关闭 tab 时联动断开会话**：closeTab 若 tab 有 sessionId 且是最后引用，自动调用 session_disconnect（当前存在泄漏隐患）
4. **快捷键**：Cmd/Ctrl+T 新建会话、Cmd/Ctrl+W 关闭 tab、Cmd/Ctrl+B 切换左栏、Cmd/Ctrl+M 切换监控面板
5. **SideBar 会话状态指示**：列表项显示连接中/已连接/断开 状态点

## 四、代码/架构质量优化

1. **错误处理**：Tauri command 的 `Result<T, String>` 统一改为结构化错误（新增 `crates/desktop/src/error.rs`，thiserror 定义 AppError，序列化为 `{code, message}`），前端 services 统一解析展示
2. **UI store 补全**：tabs store 补充 closeTab 的会话清理钩子；session 状态集中到 `stores/sessions.ts`，避免分散
3. **TerminalView 背压**：高频 terminal_output 事件改用 Tauri `Channel`（tauri 2 ipc::Channel）替代全局 emit，减少序列化开销
4. **清理注销**：session_disconnect 中同时停止 monitor 采样 task（cancellation via CancellationToken）

## 五、实施顺序（4 个阶段）

1. **阶段 1**：布局重构（三栏 + 折叠 + layout store）
2. **阶段 2**：监控后端（ssh-core exec → monitor 模块 → 命令/事件）+ 右栏监控 UI
3. **阶段 3**：体验优化（Host Key 弹窗、断线重连、快捷键、关闭联动）
4. **阶段 4**：代码质量（结构化错误、Channel 优化、清理）

每阶段完成后 `cargo build` + `pnpm build` 验证，监控解析对无 /proc 的 macOS 提供降级方案（top/df 命令解析）。
