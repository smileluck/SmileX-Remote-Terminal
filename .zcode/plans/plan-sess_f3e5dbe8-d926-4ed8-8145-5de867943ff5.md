# 文件管理改造：SFTP 流式传输 + UU远程式传输管理

**结论先行**：SFTP 协议本身兼容性没问题（OpenSSH 默认子系统，保持为主路径），问题出在实现层——整文件进内存、无进度/取消/队列。本次改造做「核心传输层 + UU远程式交互」，形态为「侧栏增强 + 独立传输管理弹窗」。tar-over-exec 兼容降级本次不做（后续单独迭代）。

## 架构总览

- **上传**：前端用原生 dialog 选本地文件/文件夹（拿到绝对路径）→ Rust 后台任务用 `tokio::fs` 流式读本地文件 → SFTP `File` 句柄分块写远端。**数据完全不走 JSON IPC**。
- **下载**：Rust 后台任务用 SFTP `File` 句柄（AsyncRead + AsyncSeek）分块读 → 流式写本地文件（下载目录可配、重名自动加 ` (1)` 后缀）。
- **进度**：Rust 侧 TransferManager 聚合，全局事件 `transfer_event` 推送（遵循 events.rs 现有 camelCase payload + serde 单测约定）。
- **队列**：Rust 侧信号量限并发（2 个文件同时传），文件夹传输先递归展开成子任务，总量预知 → 精确进度。
- **暂停/恢复**：CancellationToken + 按已传字节数 offset 续传（下载 seek 远端+本地 append；上传远端 open_with_flags 不截断 + seek）。

## 阶段 1：后端流式与传输管理器（Rust）

1. **`crates/ssh-core/src/sftp.rs` 扩展**（`russh-sftp` 锁定 "2.4"）：
   - 新增：`stat()`（预知文件大小）、`copy_out(remote_path, offset, &mut 本地 writer, cancel)` / `copy_in(&mut 本地 reader, remote_path, offset, resume: bool, cancel)` 流式分块传输（32KB 块，内部经 mpsc 上报字节增量）、`create_dir_recursive()`（mkdir -p 语义，已存在则忽略）、`remove_recursive()`（递归删除）、`walk()`（远端递归列目录，跳过 symlink 目录防环）。
2. **`crates/desktop/src/transfer.rs`（新）**：
   - `TransferManager`：`HashMap<id, TransferRecord>`（含 group_id 聚合文件夹、kind、local/remote 路径、bytes_done/total、status、speed、error）、`Semaphore(2)` 并发限制、每个传输持 `CancellationToken`。
   - Commands：`sftp_transfer_upload(session_id, local_paths, remote_dir)` / `sftp_transfer_download(session_id, remote_paths)`（可带 save_dir）、`sftp_transfer_pause / resume / cancel / retry`、`sftp_transfers(session_id?)` 快照、`sftp_transfers_clear`。注册进 main.rs。
   - `events.rs` 新增 `TransferEventPayload`（`#[serde(rename_all = "camelCase")]` + 序列化单测，防 session_id/sessionId 静默丢失）。
   - 会话断开钩子（commands/session.rs:317 附近）：取消该会话全部进行中的传输，TransferManager 中的 sftp client 随之失效。
3. **设置项**：`download_dir`（默认 ~/Downloads），保存时重名自动去重；接入现有 settings 存储。

## 阶段 2：Tauri 插件

- 新增 `tauri-plugin-dialog`（原生选文件/文件夹/保存路径）与 `tauri-plugin-opener`（"在文件夹中显示"）：desktop Cargo.toml + lib.rs 初始化 + `capabilities/default.json` 加权限 + app/package.json 加 `@tauri-apps/plugin-dialog`、`@tauri-apps/plugin-opener`。

## 阶段 3：前端

1. **`app/src/stores/transfer.ts`（新，Pinia）**：监听 `transfer_event`、初始化拉快照、按 group 聚合进度/速度、活跃计数。
2. **`app/src/services/sftp.ts`**：新增传输类 API；旧的 `upload(字节)` / `download` 迁移后删除。
3. **`FilePanel.vue` 增强**：
   - 工具栏：上传文件 / 上传文件夹（dialog）、传输管理入口（带活跃数徽标）。
   - 拖拽上传：`getCurrentWebview().onDragDropEvent`（Tauri v2，提供本地绝对路径），拖到终端区显示高亮遮罩，落点上传到当前远端 cwd。
   - 目录支持递归下载与递归删除（删除前 NPopconfirm 确认）；行右键 NDropdown（下载/重命名/删除）。
4. **`TransferManager.vue`（新）** + App.vue 挂全局右下角 FAB（活跃传输数 + 总速度徽标，跨 tab 存活）：
   - 弹窗列表按 group 展示：方向图标、名称、聚合进度条（文件夹显示 文件数/总大小）、实时速度、状态 tag（排队/传输中/已暂停/完成/失败/已取消）、操作（暂停/恢复/取消/重试/清除）、已完成下载「在文件夹中显示」；底部「清除已完成」。
5. **设置页**：新增「文件传输」小节——下载目录选择器。

## 阶段 4：验证

- `cargo test -p ssh-core -p smilex-desktop`（含新 payload serde 测试）、`vue-tsc --noEmit`。
- `pnpm tauri dev` 连真实服务器手工验证：≥1GB 大文件上传/下载（观察内存稳定不 OOM）、进度/速度、中途取消、暂停/恢复续传、文件夹递归双向、重名去重、拖拽上传、SFTP 被禁的服务器给出明确错误提示。

## 明确不在本次范围

tar-over-exec 降级兜底、Zmodem(rz/sz)、多句柄并行分片提速（大文件单流受 RTT 限制，后续优化项）、本地↔远程双栏浏览器、拖出下载。

## 实施所需权限

安装前端依赖（pnpm）、cargo 构建/测试、启动 `pnpm tauri dev` 做手工验证。
