# 修复：同一服务器多连接 tab 内容互相串台

## 根因

后端无问题（每次连接生成新 UUID 会话 + 独立 PTY，输出走 ipc::Channel 点对点）。问题在前端：

- `app/src/components/layout/MainContent.vue:31` 的 `<TerminalView :tab="tab" />` 无 `:key`，切换 tab 时 Vue 复用同一个组件树/xterm 实例
- `app/src/composables/useTerminal.ts:55-64` `bind()` 切换 sessionId 时旧会话的输出 handler 残留在全局 Map 中（`services/session.ts:14`），旧会话输出继续写入被复用的 xterm → 串台
- `useTerminal.ts:97-120` `attachInput()` 每次 bind 重复挂 `t.onData`，击键重复发送
- `services/session.ts:44-53` `handlers.set()` 覆盖语义：多个消费者绑定同一 sessionId 时后者抢占、前者静默

## 修复方案

### 1. MainContent.vue — 每个 tab 常驻独立的 TerminalView（核心修复）

把 SSH 视图从"单实例复用 + v-if"改为"per-tab 常驻渲染 + v-show"：

```vue
<div v-for="t in sshTabs" :key="t.id" v-show="t.id === tab?.id" class="tab-view">
  <TerminalView :tab="t" />
</div>
```

- `sshTabs` = computed(`tabs.tabs.filter(t => t.kind === 'ssh')`)
- DesktopView / SettingsView / 空状态分支保持原 v-if 逻辑（注意 v-for 元素不带 v-if，避免打断 v-else-if 链）
- 新增 `.tab-view` 样式（flex:1 + min-width/height:0，撑满容器）
- 效果：每个 tab 拥有自己的 xterm 实例与分屏状态，切走仅 display:none，**终端历史内容保留**；关闭 tab 时 v-for 移除节点 → 正常触发现有的 `onUnmounted` 会话清理逻辑

### 2. useTerminal.ts — bind 时解绑旧会话 + 输入只挂一次（纵深防御）

- `bind()` 绑定新 id 前先 `sessionService.unbindOutput(sessionId.value)`（若非空），杜绝 handler 残留
- `attachInput()` 加幂等保护（模块级 `inputAttached` 标志），`onData`/`onResize` 只注册一次

### 3. services/session.ts — handlers 改为多消费者集合

- `handlers: Map<string, Set<cb>>`：`bindOutput` 加入 Set，`unbindOutput` 从 Set 移除（空则删 key），Channel `onmessage` 遍历 Set 分发
- 修复"分屏绑定现有会话"时两个 pane 只有一个能看到输出的问题
- pending 缓冲回放逻辑保持不变（首个 bind 回放）

### 4. PaneTerminal.vue — v-show 切换的尺寸防御

- ResizeObserver 回调增加容器可见性检查（`containerRef.value?.clientWidth` 大于 0 才 fit），避免 display:none 期间触发无效 fit

## 验证

1. `cd app && pnpm exec vue-tsc --noEmit`（或项目现有 typecheck/build script）确认无类型错误
2. 根目录 `pnpm tauri dev` 手动验证：
   - 同一 profile 开两个连接 tab：两边各自输入/输出完全隔离，击键不重复（如按一次退格只删一个字符）
   - tab1 跑持续输出（`top`），切到 tab2 再切回：tab1 内容保留且未混入 tab2 输出
   - 分屏 pane"绑定现有会话"：两个 pane 都实时收到输出
   - 关闭 tab 后对应 SSH 会话正常断开
   - 切 tab 后调整窗口大小、主题切换正常

## 暂不处理（注明后续可选）

- DesktopView 桌面 tab 存在类似的组件复用隐患，但视频流不宜常驻隐藏渲染，且不在本次报告范围，保持现状
